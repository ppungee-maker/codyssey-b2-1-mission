## 1. 5분 요약 — 무엇을 만드는 건가요?

"이런 앱을 만들고 싶다" 는 생각을 **그림으로 보여줄 수 있는 시안(mockup)** 3장으로 만들고,
그걸 Figma 에 올려 **버튼을 누르면 다음 화면으로 넘어가는 클릭 가능한 프로토타입**으로 바꿉니다.

디자인 기술이 없어도 됩니다. **글(프롬프트)로 그림을 주문**하고, 결과를 보고 주문서를 고치는 반복이 전부입니다.
이 미션의 채점 핵심도 예쁜 그림이 아니라 **"왜 그렇게 주문했고, 왜 그렇게 고쳤는지"** 입니다.

## 4. 화면 설계 — 사용자 목표부터 정하고 그림을 주문했습니다

여기가 **가장 많이 빠뜨리는 부분**입니다. 그림을 먼저 만들면 "왜 이 배치인가" 를 나중에 설명할 수 없습니다.

### 4-1. 사용자 목표 (딱 1개)

> **"처음 앱을 켠 사용자가 3번의 탭 안에 목적지를 고르고 항공권 가격을 확인해 예약 버튼까지 도달한다."**

목표를 하나로 좁힌 이유: 목표가 2개 이상이면(예: "예약도 하고 커뮤니티도 활성화") 화면마다
우선순위가 충돌해 **무엇을 크게 둘지 결정할 수 없습니다.** 시안 단계에서는 목표 1개가 정답입니다.

### 4-2. 핵심 플로우 3단계 (메인 → 상세 → 마이페이지)

```
[1] 메인(탐색)            [2] 상세(결정)              [3] 마이페이지(확인)
목적지를 고른다     →     가격을 확인하고 예약한다   →   내 예약이 잘 됐는지 본다
"어디 갈까?"              "이 가격이면 살까?"           "제대로 예약됐나?"
```

**왜 이 3단계인가** — 여행 예약 사용자의 심리는 항상 아래 3구간을 지납니다.

| 단계 | 사용자의 질문 | 그래서 화면이 해야 할 일 | 이 시안의 대응 |
|---|---|---|---|
| 탐색 | "어디로 갈까?" | **선택지를 시각적으로** 보여주기 | 큰 사진 카드 3개(Beach/City/Mountain) |
| 결정 | "얼마야? 살까?" | **결정 변수(가격)를 가장 크게**, 행동 버튼 1개 | `$482` 최대 크기 + `Book Now` 단일 CTA |
| 확인 | "제대로 됐나?" | **상태를 한눈에** 보여 안심시키기 | 예약 3건 + 파란 체크 배지 |

**왜 '목록 페이지' 대신 '마이페이지' 를 3번째로 골랐나**: 미션은 "메인·목록·상세 등 **역할이 구분되는** 구성"을
요구합니다. 목록을 넣으면 메인(카드 그리드)과 시각적으로 거의 같아져 **역할 구분이 흐려집니다.**
반면 마이페이지는 레이아웃(프로필 + 리스트 + 상태 배지)이 완전히 달라 **구분이 뚜렷**하고,
"예약 확인" 이라는 사용자 목표의 마지막 구간을 덮습니다.

### 4-3. 정보 구조 — 무엇을 위에, 무엇을 크게 두었나 (배치 기준)

공통 기준 3가지를 먼저 정하고, 화면마다 적용했습니다.

1. **위에서 아래로 = 중요한 것부터.** 모바일은 엄지로 스크롤하므로 첫 화면(상단 1/3)에 목적을 둔다.
2. **크기 = 결정 가중치.** 사용자가 판단에 쓰는 값을 가장 크게 만든다(상세 화면의 가격).
3. **행동은 하나만.** 화면당 주요 버튼(CTA) 1개 — 두 개 이상이면 사용자가 멈춘다.

| 화면 | 배치 순서(위→아래) | 왜 이 순서인가 | 동선(어디로 이어지나) |
|---|---|---|---|
| **메인** | ① 검색바(아이콘만) ② `Destinations` 큰 제목 ③ 사진 카드 3개 ④ 하단 내비 | 목적지가 이미 정해진 사용자는 ①로 바로 탈출, 아직 못 정한 사용자는 ③에서 사진으로 고른다 — **두 유형을 한 화면에서 모두 처리** | 카드 탭 → 상세 |
| **상세** | ① 항공기 배너 + 뒤로가기 ② `JFK → LAX` ③ `$482` ④ `Book Now` | 감성 확인(①) → 사실 확인(②) → **결정 변수(③, 가장 큼)** → 행동(④). 하단 내비를 **의도적으로 제거**해 결정 단계에서 이탈 경로를 없앰 | 뒤로 → 메인 / Book Now → 마이페이지 |
| **마이페이지** | ① 프로필(아바타 + 이름) ② 예약 카드 3건(썸네일-도시명-체크 배지) ③ 하단 내비 4아이콘 | ①로 "내 계정" 을 확인시키고, ②는 **좌(썸네일) → 중(도시) → 우(상태)** 로 눈이 가는 Z 스캔 배치. 상태는 글자 대신 배지로 = 0.5초 판단 | 내비 → 전역 이동 |

> 💡 **왜 상세 화면만 하단 내비가 없나요?** 결제·예약 직전 화면에서 다른 메뉴로 가는 길을 열어두면
> 이탈률이 올라갑니다. 실제 커머스 앱들도 결제 퍼널에서 전역 내비를 감춥니다.
> **"화면마다 내비가 있어야 일관성" 이 아니라, 목적에 따라 의도적으로 빼는 것도 설계**입니다.

## 5. 프롬프트 개선 — 무엇이 깨졌고, 어떻게 고쳤나

전문(화면 3개 × 초안/최종 프롬프트 원문 + 결과 차이)은 [`worklog.md`](worklog.md) 에 있습니다.
여기서는 **원리 3가지**만 정리합니다.

### 5-1. 발견한 규칙: AI 는 "큰 단문" 은 잘 쓰고 "작은 다항목" 은 반드시 깬다

| 텍스트 종류 | 실제 결과 |
|---|---|
| 큰 볼드 단어 1~2개 (`JFK`, `LAX`, `$482`, `Book Now`, `Paris`) | ✅ 거의 항상 정확 |
| 문단 설명, 작은 보조 라벨 (운임 규정, 좌석 옵션, 내비 라벨) | ❌ `Rataogies and your woer...`, `Sellect seat`, `Preouly taske: 18` 처럼 깨짐 |

### 5-2. 그래서 프롬프트를 이렇게 고쳤다 (3단계 강화)

1. **"텍스트를 최소화해줘" → 실패.** 초안에서 이렇게 부탁했지만 검색창 placeholder·내비 라벨이 전부 깨졌습니다.
   부드러운 요청은 무시됩니다.
2. **"정확히 한 단어" 로 개수를 못박기.** `each with exactly ONE large bold single short word` →
   `Beach`, `City`, `Mountain` 이 정확히 나왔습니다.
3. **"작은 글자·문단은 아예 그리지 말라" 는 금지문 추가.** `Do not render any small text, paragraphs,
   or sentences anywhere in the image.` → 깨질 대상 자체가 사라졌습니다.

즉 **부탁(minimize) → 수량 지정(exactly ONE) → 금지(Do not render)** 순으로 강도를 올린 것이 개선의 축입니다.

### 5-3. 후가공을 왜 인페인팅이 아니라 '프롬프트 재설계' 로 했나

- 인페인팅은 **깨진 글자를 지우고 그 자리만 다시 그리는** 방식입니다. 그런데 같은 모델이 같은 자리에
  다시 그리면 **또 깨질 확률이 높습니다**(원인이 모델의 글자 렌더링 한계이므로).
- 반면 "그 텍스트를 요구하지 않기" 는 원인을 없애는 방식이라 **1회 재생성으로 완전히 해결**됐습니다.
- 비용도 근거입니다: 인페인팅 반복은 호출 수가 늘고(회당 2,000 vt), 결과 검수도 매번 필요합니다.
  이번엔 화면당 재생성 1회(총 6회, 12,000 vt)로 끝났습니다.
- 다만 **정보 전달에 반드시 글자가 필요한 화면**(약관·표 등)에서는 이 전략이 통하지 않습니다.
  그 경우 Figma 에서 **텍스트 레이어를 위에 덮는 방식**이 정답이며, §7-3 에 그 절차를 넣어 두었습니다.

## 6. 일관성 유지 — 전략 선택 이유와 **적용 전/후 비교**

### 6-1. 왜 '시드 고정' 이 아니라 '스타일 키워드 반복' 을 골랐나

| 전략 | 이번에 쓸 수 있었나 | 판단 |
|---|---|---|
| **시드(seed) 고정** | ❌ 네이토 이미지 API 는 시드 파라미터를 노출하지 않는다(요청 필드에 없음) | 쓸 수 없어 제외 |
| **이미지 레퍼런스(img2img)** | ❌ 이 엔드포인트는 텍스트 프롬프트만 받는다(참조 이미지 입력 불가) | 쓸 수 없어 제외 |
| **스타일 키워드 반복** | ✅ 프롬프트 문구만으로 가능 | **채택** |
| **후처리 통일(Figma)** | ✅ 배경·아이콘 색을 레이어로 덮어 맞출 수 있다 | 보완책으로 채택(§7-3) |

즉 이 선택은 취향이 아니라 **도구가 제공하는 제어 수단이 프롬프트 텍스트뿐이었기 때문**입니다.
"시드를 고정하면 좋다" 는 일반론을 그대로 적으면 이 환경에서는 **실행 불가능한 답변**이 됩니다.

### 6-2. 적용 방법 — 3화면 프롬프트 꼬리에 **똑같은 4요소**를 붙였다

```
Clean minimal style, blue and white color palette,
high-fidelity Figma-style UI design, portrait 9:16 mobile screen
```

- **초안에서는 이 문구가 화면마다 달랐습니다**: 화면1 `warm blue and white color theme, soft rounded cards` /
  화면2·3 `blue and white color theme` — `warm` 유무, `soft rounded cards` 유무가 갈렸습니다.
- 최종에서는 **어휘까지 동일하게** 복사해 붙였습니다. 스타일 지시는 동의어로 바꾸면 결과가 흔들립니다.

### 6-3. 전/후 비교 — 화면 간 체크포인트 6개로 실제 확인

최종 3장을 나란히 놓고 항목별로 확인한 결과입니다(이미지 육안 검증).

| 체크포인트 | 초안 3장 | 최종 3장 | 개선 |
|---|---|---|---|
| 화면 비율 | 9:16 통일 | 9:16 통일 | 유지 ✅ |
| 카드/버튼 라운딩 | 화면1만 강한 라운드, 화면2는 각진 배너 | 3장 모두 큰 라운드(≈16px 감각) | **개선 ✅** |
| 텍스트 깨짐 | 화면당 2~4곳 | **0곳** | **개선 ✅** |
| 텍스트 색 | 화면별로 남색/검정 혼재 | 짙은 네이비 계열로 수렴(화면3만 약간 차콜) | **부분 개선 △** |
| 배경색 | 순백/연회색 혼재 | 화면1 순백 · 화면2·3 연회색 + 흰 카드 | **미해결 ✗** |
| 강조 파랑 | 화면별 상이 | 화면2 진한 파랑 버튼 · 화면3 밝은 하늘파랑 배지 | **미해결 ✗** |

**정직한 결론**: 스타일 키워드 반복으로 **비율·라운딩·텍스트 품질·글자색은 수렴**했지만,
**배경색과 강조 파랑의 채도는 끝까지 완전히 맞지 않았습니다.** 시드 고정·레퍼런스 입력이
불가능한 환경에서는 프롬프트만으로 색을 픽셀 단위까지 통일할 수 없다는 것이 이번 실측 결론입니다.
→ 그래서 **Figma 단계에서 배경 레이어 1개와 아이콘 색 오버레이로 통일**하는 보완책을 §7-3 에 두었습니다.

## 7. Figma 프로토타입 만들기 (클릭 순서대로)

Figma 를 처음 켠 사람 기준으로 적었습니다. 총 15~20분.

### 7-1. 이미지 배치

1. [figma.com](https://figma.com) 로그인 → 왼쪽 상단 `+ Design file` 클릭
2. 툴바에서 `#` 모양 **Frame** 선택 → 오른쪽 패널에서 `Phone` → `iPhone 16` (또는 `1024×1536` 직접 입력) 선택
3. 같은 방법으로 프레임을 총 **3개** 만들어 좌우로 나란히 배치
4. `images/final/` 의 PNG 3장을 파일 탐색기에서 **드래그 앤 드롭** → 각 프레임 안에 1장씩
5. 이미지를 프레임 크기에 맞춤: 이미지 선택 → 오른쪽 패널 `W`/`H` 를 프레임과 동일하게
6. 프레임 이름 변경(더블클릭): `01-Main`, `02-Detail`, `03-MyPage` — **이름이 프로토타입 흐름에서 그대로 보입니다**
7. 여기서 화면 전체를 캡처 → `captures/figma/01-overall-structure.png`

### 7-2. 핫스팟(클릭 영역) 연결 — 3개만 만들면 됩니다

우측 상단 탭을 `Design` → **`Prototype`** 으로 바꾼 뒤:

| # | 어디를 누르면 | 어디로 가나 | 만드는 방법 |
|---|---|---|---|
| 1 | 메인의 `Beach` 카드 영역 | `02-Detail` | 카드 위에 투명 사각형(`R`)을 그리고 Fill 투명도 0% → 선택 후 오른쪽 ⊕ 를 드래그해 상세 프레임에 연결 |
| 2 | 상세의 `Book Now` 버튼 | `03-MyPage` | 버튼 위에 투명 사각형 → ⊕ 드래그 |
| 3 | 상세의 뒤로가기(←) 아이콘 | `01-Main` | 아이콘 위에 투명 사각형 → ⊕ 드래그 → Animation 은 `Move out` |

- 연결 후 `Interaction` 패널에서 `On click` → `Navigate to` 인지 확인
- 캡처 → `captures/figma/02-hotspot-setup.png`
- 우측 상단 ▶ `Present` 로 실제 클릭 테스트 → 캡처 `captures/figma/03-present-flow.png`
- 마지막에 `Share` → `Anyone with the link` → **Copy link** → 이 README 상단 "Figma 프로젝트 링크" 에 붙여넣기

### 7-3. (보완) 일관성 통일 + 글자 덮어쓰기

§6-3 에서 남은 편차를 Figma 에서 마무리하는 방법입니다.

1. **배경 통일**: 3프레임 뒤에 같은 색(`#F4F6FA`) 사각형을 깔고 이미지 여백을 덮는다
2. **강조색 통일**: 화면3 체크 배지 위에 화면2 버튼 색과 같은 원을 올린다(Fill 스포이드로 색 추출)
3. **글자 교체가 필요하면**: 원하는 위치에 `T` 로 텍스트 레이어를 만들고, 아래 깨진 글자 영역을
   배경색 사각형으로 덮은 뒤 그 위에 얹는다 — 이것이 **인페인팅 없이 텍스트를 고치는 표준 방법**입니다

## 10. 자주 겪는 문제와 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 이미지 속 글자가 외계어로 나온다 | 작은 글자·문단은 모델이 못 그린다 | 그 텍스트를 **요구하지 않기**(§5-2 금지문) |
| "텍스트 최소화" 를 넣었는데도 깨진다 | 부드러운 요청은 무시된다 | `exactly ONE word`, `Do not render…` 처럼 **수량·금지**로 |
| 화면마다 색·분위기가 다르다 | 스타일 문구가 화면별로 달랐다 | 스타일 4요소를 **글자 그대로 복사**해 반복(§6-2) |
| 그래도 배경색이 안 맞는다 | 시드 고정이 불가능한 도구 제약 | Figma 에서 배경 레이어로 통일(§7-3) |
| Figma 에서 카드를 눌러도 안 넘어간다 | 이미지 위에 클릭 영역을 안 만들었다 | 투명 사각형을 올리고 ⊕ 드래그(§7-2) |
| 프레임 이름이 그대로 노출돼 지저분하다 | 기본 이름(`Frame 1`) 유지 | `01-Main` 처럼 의미 있는 이름으로(§7-1) |
